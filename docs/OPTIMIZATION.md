# Constant optimization

`optimize(instructions)` returns `(optimized_instructions, changes)`. It works on
ordered IR rather than editing source text or evaluating Python. The input IR is
left unchanged.

## Transformations

1. Constant folding computes ADD and MUL instructions when both operands are
   known integers.
2. Constant propagation replaces references to computed temporaries in later
   arithmetic and delivery values.
3. Folded temporary assignments are removed after recording their constant value.

Example:

```text
Before                         After
t1 = 2 * 2
t2 = 2 + t1
  EMIT_DELIVERY run, t2           EMIT_DELIVERY run, 6
```

Temporary names generated by the IR generator are unique. Unresolved arithmetic
is retained, with any known operand substituted. Over and innings boundaries,
flags, delivery order, delivery kinds, and source metadata are preserved. A
zero-run delivery or wicket is never removed.

Programs containing only numeric deliveries need no transformation and return
an empty changes list. The UI displays one unchanged listing in this case.
Otherwise it shows instruction counts, individual fold explanations, and aligned
before/after code with removed and substituted lines highlighted.

Arithmetic validity and the intermediate numeric limit are checked by semantic
analysis before this phase. This pass does not perform cricket validation.

Tests execute both original and optimized IR through the same target generator
and compare complete JSON scoring results, including extras and delivery history.
Real API tests also verify six-phase completion and the resulting scorecard.
